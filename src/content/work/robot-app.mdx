## The problem

People set robots up on site: standing next to the machine, on its touchscreen, often without a network. So the app runs on the robot itself. It talks to the robot's ROS software in real time and has to stay smooth while pose, laser scans and diagnostics arrive ten to twenty times a second.

## What I built

The app and its server, in one monorepo with shared packages for events, logging and the UI kit. The same repo ships a guided update wizard for installing new robot software.

- **Editing:** a map and zone editor on a Konva canvas, and mission and route-graph editors on React Flow.
- **Seeing:** a layered 3D view in Three.js: occupancy map, live mapping cloud, laser scan, planned path, waypoints, zones and safety fields, each a layer that can be switched on or off.
- **Reporting:** analytics charts, heatmaps and PDF reports generated in the browser.
- **The server:** Hono with every route described in OpenAPI, MongoDB and Redis, Socket.io to the screen, and rosbridge to the robot.
- **Access:** pages check the user's role before they render, so typing a URL doesn't skip a permission.

## Hard parts

**Sensor-rate data in React.** A component that re-renders at sensor rate stalls the screen. Fast state lives in a store that the canvas layers subscribe to directly; they move Konva shapes, map markers and Three.js objects themselves, and React only re-renders when something a person reads has changed.

**Hours of uptime on the GPU.** The app stays open for a whole shift. Every 3D layer disposes its geometries, materials and textures when it changes, so memory stays flat instead of creeping up until the screen stutters.

**An assistant with no internet.** The robot's documentation is split into chunks, embedded and stored in ChromaDB on the robot. Ollama runs the model locally, and LangChain pulls in the relevant sections so answers are grounded in the robot's own docs.

## Shipping updates to robots

The same repo ships a guided installer for robot software. It checks the hardware, lets someone pick versions and add packages, shows a review, then installs. A small authenticated service on the robot does the deploying.
